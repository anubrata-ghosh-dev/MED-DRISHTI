# Live Demonstration Guide — Med-Drishti

**System:** AI-Assisted Clinical Intake Platform
**Target:** Hackathon Evaluators, Clinical Stakeholders, & Engineering Reviewers
**URL Frontend:** `http://localhost:3000`
**URL Backend:** `http://localhost:8000`

---

## 1. System Launch Instructions

You can run Med-Drishti using either Docker Compose or standalone local servers:

### Option A: Docker Compose (Recommended)
From the repository root, start both backend and frontend containers:

```bash
docker-compose up --build
```
- Backend API: `http://localhost:8000`
- Frontend Kiosk: `http://localhost:3000`

---

### Option B: Local Development Run

**Terminal 1 — Backend:**
```bash
cd backend
python3 -m pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Terminal 2 — Frontend:**
```bash
cd frontend
npm install
npm run dev
```

## 4. Step-by-Step Kiosk Intake Walkthrough

Open your web browser and navigate to `http://localhost:3000`.

### Step 1: Welcome & Landing (`/`)
- Demonstrates the patient-facing touch kiosk interface.
- Click **"Start Intake"** to begin.

### Step 2: Language Selection (`/language`)
- Select your preferred regional language (e.g. **Hindi** or **English**).
- Notice that prompt cards reflect regional vernacular. Click **"Continue"**.

### Step 3: Patient Registration (`/register`)
- Enter patient demographic information:
  - **Name:** `Aarav Patel`
  - **Date of Birth:** `1990-08-20`
  - **Gender:** `Male`
  - **Phone:** `9876543210`
  - **ABHA ID:** `14-1234-5678-9012` (or click "Generate New ABHA")
- Click **"Register & Proceed"**.

### Step 4: Digital Informed Consent (`/consent`)
- Displays an explicit bilingual consent agreement explaining data collection and voice processing under DPDPA principles.
- Check the consent authorizations and click **"I Agree & Continue"**.

### Step 5: Multimodal Adaptive Intake (`/intake`)
- **Question 1 (Chief Complaint):**
  - Click the **Microphone** icon and speak: *"I have severe chest pain and breathlessness since morning."*
  - (Alternatively, type into the text area).
  - Click **"Next"**.
- **Dynamic Branching:**
  - Notice that the system detects cardiac keywords and automatically adapts the next question:
    - *"Is the chest pain sharp, crushing, or burning? Does it spread to your left arm?"*
- Continue answering the adaptive questions (medications, known allergies, duration).
- Complete the dialogue.

### Step 6: Medical Document Upload (`/medical-history`)
- Upload a physical document scan or prescription photo.
- The system automatically triggers `LocalOCRProvider` (Tesseract/EasyOCR).
- Extracted medications and dates appear in real time with extraction confidence bars.
- Click **"Complete Intake"**.

### Step 7: Done Screen & Auto-Reset (`/done`)
- Patient receives their OPD Queue Token number (e.g., `#TK-104`).
- A 30-second countdown timer visibly ticks down.
- Once the timer expires, the kiosk automatically purges local credentials and resets to `/` for the next patient.

## 5. Staff & Clinical Review Dashboards

### 5.1 Triage Nurse Dashboard (`/triage`)
- Navigate to `http://localhost:3000/triage`.
- Displays real-time clinical alerts generated by the deterministic red-flag engine.
- **Inspect Patient A (Rahul Sharma):**
  - Red-flag banner: **CRITICAL — Acute Cardiac Pattern Detected**.
  - Triage nurse can click **"Acknowledge / Review"** to sign off that emergency vitals were expedited.

### 5.2 Physician Review Dashboard (`/doctor`)
- Navigate to `http://localhost:3000/doctor`.
- **Queue Prioritization:** Patients are sorted with `CRITICAL` triage cases at the very top.
- Click on **Rahul Sharma** to open the case review modal:
  1. **Subjective Intake:** View transcribed chief complaint and HPI.
  2. **AI Extracted Entities:** View medications with confidence ratings.
  3. **Uploaded Records:** View the original scanned prescription and OCR text.
  4. **Clinical Intelligence Panel:** Review drug-drug interaction warnings and abnormal vitals.
- **Verification:**
  - Doctor edits any imperfect AI transcriptions.
  - Adds physician clinical notes: *"Urgent ECG ordered. Administered aspirin."*
  - Clicks **"Verify & Complete Encounter"**.
  - The encounter status turns to `completed`, and an entry is committed to the immutable audit log.

## 6. Interoperability & Government Interface Demonstration

### 6.1 HL7 FHIR R4 Bundle Export
To verify that the verified encounter produces an international healthcare exchange standard, run:

```bash
curl -s http://localhost:8000/api/v1/fhir/1 | python3 -m json.tool | head -n 40
```

Demonstrates an HL7 FHIR R4 `collection` Bundle containing `Patient`, `Encounter`, `Observation`, and `MedicationStatement` resources.

---

### 6.2 ABDM Record Sharing Simulation
To demonstrate ABDM Health Information Exchange push:

```bash
curl -X POST http://localhost:8000/api/v1/abdm/share-record \
  -H "Content-Type: application/json" \
  -d '{"session_id": 1}'
```

Response:
```json
{
  "status": "success",
  "consent_id": "CONSENT_5a8f12c9",
  "session_id": 1,
  "fhir_resource_count": 5
}
```
